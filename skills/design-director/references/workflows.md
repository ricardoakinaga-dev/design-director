# Workflows

## Greenfield

Understand audience and product truth → define thesis and anti-territory → choose variant → establish tokens → concept the full relevant surface → create asset plan → implement with an owner → run responsive/accessibility QA → independent critique → fix and hand off.

## Existing project

Inventory routes, components, tokens, fonts, assets, and states → capture baseline → identify preserve/change boundaries → issue a delta brief → change the smallest coherent surface → run visual regression and interaction checks → compare before/after → critique → document migrations and residual debt.

## Design audit

Inspect the real surface → score applicable dimensions → list critical/high/medium/low findings → separate symptom from root cause → propose prioritized fixes → mark runtime checks as observed, not run, or blocked. Do not redesign merely because the user asked for a diagnosis.

## Visual reconstruction

Inspect reference at native dimensions → decompose layers and observations → inventory copy/assets → implement semantic structure → compare at the reference viewport and responsive fixtures → correct the fidelity ledger → rerender → have a fresh critic inspect. Never make the screenshot the UI.

## Asset-led request

Define asset role and consumer → choose raster/SVG/code → compile prompt or vector brief → classify references and identity locks → generate/edit or implement → inspect output → verify crop, text, alpha, size, provenance, and loadability → integrate without overwrite.

## Simple isolated edit

Use a proportional route. Preserve surrounding behavior, edit only the owned asset or component, run the smallest relevant check, and do not force a full concept or browser loop when it adds no evidence.

## Completion contract

Stop only when the applicable required criteria pass, the artifact is integrated, evidence is current, no blocking gap remains, and limitations are explicit. For benchmarked work, serialize `benchmark → artifact → render → inspection → score → critique → iteration → final decision`; a missing required link is `NOT_RUN`/`BLOCKED`. Use an adaptive iteration budget and record the stop reason. A user may explicitly override a threshold or stop early, but the override records scope, reason, tradeoff, compensating evidence, authority and revalidation trigger; it never silently becomes AAA. If an optional tool is missing, finish the unaffected scope and mark the dependent evidence blocked.

## Evidence-driven benchmark

When a golden or user-defined benchmark applies, load its machine-readable contract from `benchmarks/`. Build or route the artifact to the owning specialist, render the declared viewports/states, inspect semantic regions, record the visual ledger, obtain the blinded read-only critic packet, score only applicable dimensions, and fix the largest material gap within budget. After every material fix, capture a new render and fresh critique. The repository validators verify bindings and gates; they do not infer visual quality from source text.

## Local package checks

For this skill package, run the official frontmatter and plugin validators, then `scripts/validate_package.py` and `scripts/smoke_evals.py evals/evals.json`. Run `scripts/check_contrast.py` for known color pairs, `scripts/audit_assets.py` for output naming/size, pixel-stream decodability, and dimensions, `scripts/compare_visual.py` for native PNG reference/capture metrics, and the test suite with `python3 -B -m unittest discover -s scripts/tests -v`. These checks validate the package and helper/eval contracts; they do not replace a browser render, image inspection, tool trace, or independent visual critic.
